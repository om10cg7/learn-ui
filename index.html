空間UI（スペーシャルUI）

Spatial UI / visionOS Glass Material

グラスモーフィズムを3D空間向けに進化させたAppleの最新デザイン。ガラスの上端が光を反射する「スペキュラーハイライト（鋭い白縁）」と、視線を合わせた時にふわっと明るく浮き上がるホバー表現が特徴です。

もっと詳しく
仕組み・特徴
ウィンドウは「ガラス板」として空間に浮かぶ。上端の鋭い白縁（スペキュラーハイライト）が環境光の反射を、深く広いドロップシャドウが空中に浮く高さを表す。視線を合わせると少し明るくなるホバー表現で、操作対象を知らせる。
使いどころ
3D空間やARで、現実の背景と重なるパネル・ウィンドウ。Web では背景ぼかし＋細い白縁＋大きな影の組み合わせで雰囲気だけ再現できる。
注意点
背景が透けるため、背後の色次第で文字が読みにくくなる。文字の背面には必ず十分なコントラストを確保する。

ダイナミックアイランド風UI（流体モーフィング）

Dynamic Island / Fluid Morphing Pill

黒いカプセル型（ピル）の領域が、通知や再生状態に応じて液体やスライムのようにバネ挙動（スプリング物理演算）でヌルッと伸縮・変形するマイクロインタラクション。Webのフローティングナビでも大流行しています。

もっと詳しく
仕組み・特徴
黒いピル型の領域が、通知・通話・再生などの状態に合わせて形と大きさを変える。動きに「バネ（スプリング）」の物理挙動を使うので、伸びてから少し戻る粘り気のある変形になる。
使いどころ
Web でも、フローティングナビや通知バーを「状態に応じて伸縮するカプセル」にすると同じ感触が出せる。状態変化を1か所で受け止める設計にも向く。
注意点
動きが派手になりやすい。変形中に内容が読めなくなるのは避け、アニメは短く（数百ms程度）保つ。動きを減らす設定（prefers-reduced-motion）への配慮も忘れずに。

スクワークル（連続曲率の超楕円）

Squircle / Continuous Curvature Corner

「Square（四角）」＋「Circle（円）」の造語。通常のCSS角丸と違い、直線からカーブへ入る継ぎ目の曲率が徐々に変化するため、iPhoneのアイコンや筐体のような「工芸品のように滑らかな角丸」になります。

もっと詳しく
仕組み・特徴
四角と円の中間形。通常の角丸（border-radius）は直線から円弧へ急に切り替わるため、継ぎ目に曲率の段差が見える。スクワークルは曲率が少しずつ変化するので、角がなめらかに繋がって見える。
使いどころ
アプリアイコン、カード、ボタンなど、角丸を多用するUIの「上質さ」を上げたいとき。Figma の角の滑らかさ（Corner smoothing）設定や、SVG パスで近い形を作れる。
注意点
CSS の border-radius だけでは厳密には再現できない。大きな差が出るのは大きめの角丸なので、小さな要素では費用対効果が低い。

HIG バイブランシー（Vibrancy）

Apple HIG Vibrancy & Translucent Materials

Appleの公式デザイン規約（HIG）で定義されている「単なる半透明ぼかしではなく、背景の色味を鮮やかに増幅（saturate）させて前景の文字と調和させる」手法。コントロールセンターやmacOSサイドバーの核となる技術です。

もっと詳しく
仕組み・特徴
背景を単にぼかして半透明にするだけでなく、背景の色味を増幅して前景の文字やアイコンを鮮やかに見せる素材処理。背景に馴染みつつ、前景がくっきり読める状態を作る。
使いどころ
macOS・iOS のサイドバー、メニュー、コントロールセンターのような、背景が透けるパネル。Web では backdrop-filter の blur に saturate を足すと近い見た目になる。
注意点
ぼかしは描画コストが高く、低スペック端末で重くなる。透過を使うなら、背景が単色でも成立する代替スタイルを用意しておく。

グラスモーフィズム

Glassmorphism

すりガラスのように背景をぼかして透かし、細い半透明の白枠（ボーダー）でガラスの縁を表現する手法。macOS Big SurやWindows 11が採用し世界的な定着を果たしました。

もっと詳しく
仕組み・特徴
背景をぼかして透かし、細い半透明の白枠でガラスの縁を表現する。Figma では Glass エフェクト（屈折・深さ・曇り・分散・色味）を使い、グラデーション下地＋インナーシャドウ＋ハイライトを重ねて質感を作る。
使いどころ
鮮やかな背景（グラデーション、オーロラ、写真）の上に置くカードやボタン。複数の背景色の上に置いて見え方を確認するのが実務手順。
注意点
背景依存の表現なので、単体ではなく実画面で最終判断する。ボタンは Default／Hover／Pressed／Inactive／Processing／Error まで状態を定義して初めて完成する。

ニューモーフィズム

Neumorphism (Soft UI)

背景と要素をまったく同じ色にし、左上の白い光（ハイライト）と右下の暗い影（シャドウ）だけで、背景から押し出されたような凹凸を表現する手法。

もっと詳しく
仕組み・特徴
背景と要素を同じ色にして、明るい影（左上のハイライト）と暗い影（右下）の2つだけで、押し出された・押し込まれた凹凸を作る。インナーシャドウとアウターシャドウの使い分けが核。
使いどころ
装飾的な画面、状態の少ないUI部品（スイッチ、音量つまみ、電卓風UIなど）。DO は「さりげないハイライト・抑えた影・少ない色数」。
注意点
コントラストが低く、ボタンと背景の判別がつきにくい。DON'T は「深すぎる立体感・暗い影・高彩度の色」。操作が重要な画面では、輪郭や色で補う。

クレイモーフィズム

Claymorphism

粘土（クレイ）人形のようにもっちり・ぷっくりと膨らんだ3D風の質感。大きな角丸と、要素の内側に入れる2方向のインナーシャドウで作ります。

もっと詳しく
仕組み・特徴
立体感を作るのは影の「向き」。内側の左上に明るいインナーシャドウ、右下に暗いインナーシャドウを入れ、さらに外側にやわらかいドロップシャドウを足すと、ぷくっと膨らんで見える。ニューモーフィズムが背景と同色で凹凸を作るのに対し、こちらは色付きの面で膨らみを作る。
使いどころ
親しみやすいアプリ、子ども向け、イラスト調のアイコンやダッシュボードのアクセント。3Dキャラクターと合わせた世界観づくりにも向く。
注意点
影を重ねるため、要素が多いと画面全体が重く騒がしくなる。主役の数点に絞って使う。

スキューモーフィズム

Skeuomorphism

現実世界の革の縫い目、金属の光沢、物理スイッチの凹凸などをリアルに模倣する手法。スティーブ・ジョブズ時代の初期iPhone（iOS 6まで）の象徴的デザインです。

もっと詳しく
仕組み・特徴
革の縫い目、金属の光沢、物理スイッチの凹凸など、現実の物の質感をそのまま画面に写す手法。初期 iPhone（iOS 6 まで）が代表例で、「どう操作するか」を現物の見た目から直感的に伝えた。
使いどころ
初めてのデバイスに操作を教える場面、ゲームや音楽機材のUI（つまみ・フェーダー）など、現物のメタファーが価値になる場面。
注意点
表現が重く、画面ごとの作り込みコストが高い。iOS 7 で Apple がフラットデザインへ移行した理由もここにある。

フラットデザイン

Flat Design

影や立体感をすべて排除し、単色の面とタイポグラフィだけで構成する手法。2013年のiOS 7でAppleがスキューモーフィズムを捨てて全面採用し、世界の標準となりました。

もっと詳しく
仕組み・特徴
影・グラデーション・立体感を排除し、単色の面とタイポグラフィ、アイコンで構成する。2013 年の iOS 7 で Apple が全面採用して世界に広まった。
使いどころ
情報量が多く、軽さと拡張性が必要なアプリ・Webサイト。レスポンシブ対応や、デザインシステムとの相性がよい。
注意点
立体感がないぶん、ボタンかどうかが分かりにくくなりやすい。色・余白・ラベルで「押せる」ことを明示する。

ベントーUI（弁当グリッド）

Bento UI / Bento Grid

日本の幕の内弁当の仕切りのように、大きさの異なる角丸長方形カードを隙間なく並べるレイアウト。Appleの新製品発表スライドから世界中に広まった現代の王道レイアウトです。

もっと詳しく
仕組み・特徴
大きさの異なる角丸の長方形を、隙間を揃えてきっちり並べる。1枚1枚のカードが「ひとつの話題」を担うので、情報の優先順位をカードの大きさで表せる。
使いどころ
製品の特長紹介、ダッシュボード、ポートフォリオ。FlowFin のダッシュボードのように、KPI→一覧／詳細→分析と視線の流れに合わせて大きさを配分する。
注意点
カードの見た目（角丸・余白・影）を統一しないとまとまりが崩れる。モバイルでは1列に畳む設計も同時に考える。

メイソンリーレイアウト

Masonry Layout

オーロラUI / メッシュグラデーション

Aurora UI / Mesh Gradient

複数の淡い色が境界線なく溶け合い、オーロラのようにぼんやりと発光する背景表現。グラスモーフィズムの背面として抜群の相性を持ちます。

もっと詳しく
仕組み・特徴
作り方は、ぼかした大きな色の円を複数重ねる方法と、メッシュグラデーション（格子点ごとに色を指定）の2種類が主流。色相が近い色を選ぶとなめらかになり、離れた色だと濁りやすい。
使いどころ
グラスモーフィズムの背面、ヒーロー背景、ダッシュボードのアクセント。ボカシの上に置くカードがよく映える。
注意点
背景が主張しすぎると文字が読みにくい。文字を載せる面にはコントラストを確保し、画像として重くなりすぎないよう圧縮する。

5. 動き・UX原則

マイクロインタラクション

Micro-interactions

入力・タップなど小さな操作への細かい反応の設計。OTP（ワンタイムコード）入力の自動フォーカス移動、完了時のチェック＋粒子アニメーションなど、「気持ちよさ」を作る要素の総称。成功状態だけでなく、誤入力や期限切れなどエラー状態まで設計して初めて完成する。

もっと詳しく
仕組み・特徴
1つの反応は「きっかけ→反応→フィードバック」で考える。OTP入力の例では、数字を入れる（きっかけ）→次の枠へ自動でフォーカス移動（反応）→完了時にグリッド状のアニメ→緑のチェックと粒子（フィードバック）。入力の摩擦を減らし、義務的な手続きにも報酬感を作る。
使いどころ
認証、フォーム送信、ボタンの状態変化、いいね・保存など。
注意点
成功時だけでなくエラー（誤入力・期限切れ・再送）も設計して初めて完成する。派手さより、使いやすさの改善になっているかを問う。

5. 動き・UX原則

ローダー / プログレスインジケーター

Loader / Progress Indicator

読み込みの待ち時間に見せる進捗表現。円弧が25%→100%と伸びる円形ローダーやプログレスバーなど、進捗が見える形は同じ待ち時間でも短く感じさせる。Figmaではバリアントで円弧の伸びをアニメーション化できる。静止画で中身の形だけ見せるスケルトンスクリーンとは役割が違う。

もっと詳しく
仕組み・特徴
種類は大きく3つ：①終わりが分からないスピナー、②割合を示すプログレスバー・円形、③中身の形を先に見せるスケルトン。円形ローダーは、正円→一部が欠けたリング（円弧）→複製→Variants で円弧を 25%→100% に伸ばす手順で、コードなしに作れる。
使いどころ
ボタン押下後の処理中（PROCESSING 状態）、ファイル送信、ページ遷移。
注意点
進捗が分からないスピナーは不安を招く。長い待ち時間には、割合や残り時間、スケルトンを併用する。

5. 動き・UX原則

視覚階層と視線誘導（F/Zパターン）

Visual Hierarchy / Eye-tracking Patterns

大きさ・色・配置で情報の優先順位を作る原則。人の視線はWebではFパターン、視覚要素の多い画面ではZパターンで動くとされ、重要な情報やCTAはその軌道上に置くと伝わりやすい。階層が弱いサイトは「古く、信頼できない」印象の原因にもなる。

もっと詳しく
仕組み・特徴
階層を作る手段は大きさ・色・配置・余白の4つ。F パターンは、上の横線→少し下の短い横線→左の縦線の順で、情報量の多いページで見られる読み方。Z パターンは、左上→右上→左下→右下とジグザグに見る読み方で、LP のようにシンプルな画面に向く。
使いどころ
LP、ダッシュボード、ヒーロー。重要指標は最も目立つ位置に（ダッシュボードのルール1）。
注意点
目立たせる要素を増やすと階層が崩れる。主役は1つに絞る。ヒエラルキーの弱さは「古さ」の正体にもなる。

5. 動き・UX原則

デザインシステム

Design System

ボタンや入力欄などのコンポーネント、色や余白のトークン、使い方のルールを一式そろえた「一貫性の枠組み」。デザインと開発が同じ部品を共有することで、画面が増えても品質と速度が落ちない。UI/UXデザイナーの学習ロードマップでも基礎の次に置かれる重要ステップ。

もっと詳しく
仕組み・特徴
構成は3層：①トークン（色・文字・余白・角丸などの値）、②コンポーネント（ボタン・入力欄・バッジなど、全状態つき）、③使い方のルール（いつ・どこで使うか）。例として、ボタンは Default／Hover／Pressed／Inactive／Processing／Error まで揃えて、はじめて部品として完成する。
使いどころ
複数画面・複数人で作るプロダクト。ボタンの全状態、ステータスバッジ、色の役割（成功・警告・エラー）を決めておく。
注意点
作って終わりではなく、運用が要。ルールが多すぎると守られなくなるので、まず色・文字・余白・ボタンから整える。

6. タイポグラフィ・配色

フォントペアリング

Font Pairing

見出し用と本文用のフォントの組み合わせ設計。基本形は「見出しに個性のあるフォント、本文に読みやすいサンセリフ（Inter、DM Sansなど）」。例：Playfair Display＋Inter（ラグジュアリー）、Space Grotesk＋Inter（テック）、Sora＋DM Sans（AI系）。ブランドロゴもタイポグラフィでできていることが多い（Apple=Myriad Pro、VOGUE=Didot）。

もっと詳しく
仕組み・特徴
組み合わせの型は3つ。①個性の見出し＋読みやすい本文（最も基本）、②セリフ体の見出し＋サンセリフ体の本文（雑誌風）、③同じ家族の太さ違い（ExtraBold＋Regular）。Inter と DM Sans は本文役として何度も登場し、迷ったらここから選ぶのが実務的。
使いどころ
用途別の例：Playfair Display＋Inter（ラグジュアリー）、Space Grotesk＋Inter（テック／SaaS）、DM Sans（プロダクト／ダッシュボード）、Manrope＋Open Sans（フィンテック／分析）、Sora＋DM Sans（AI／スタートアップ）、Lora＋DM Sans（コンテンツ）、Outfit＋Inter（モバイル／EC）、Plus Jakarta Sans（SaaS）。
注意点
フォント数を増やしすぎない（通常は 2 種まで）。日本語表示では欧文フォントとの混植のバランスも確認する。

6. タイポグラフィ・配色

配色ハーモニー

Color Harmony

色相環上の位置関係で配色を決めるルール。代表は5種：モノクロマティック（同系色）、類似色、補色、トライアド（3色）、分裂補色。感覚ではなく「まずどのハーモニーを土台にするか」を決めるとパレット作りが迷走しない。決めた後はコントラスト比チェックで可読性を検証する。

もっと詳しく
仕組み・特徴
5つのハーモニーは、色相環（12分割）上の位置関係で決まる。同系色＝同じ色相、類似色＝隣り合う色、補色＝正反対の色、トライアド＝正三角形に並ぶ3色、分裂補色＝1色と「その補色の両隣」の組み合わせ。補色は強く目立ち、類似色はなじむので、強弱の使い分けに向く。
使いどころ
まず 5 つのうちどれを土台にするかを選び、そこから彩度・明度で調整する。暖色は食欲・行動、寒色は信頼・落ち着き、と用途で温度感を使い分ける。
注意点
配色を決めたら、コントラスト比（WebAIM Contrast Checker など）で可読性を確認する。

6. タイポグラフィ・配色

色の3属性（色相・彩度・明度）

Hue / Saturation / Brightness

色を3つの軸で捉える考え方。色相＝色の種類、彩度＝鮮やかさ、明度＝明るさ。同じダッシュボードでも属性を変えると青→緑→紫のように印象が変わる。淡色パレット作りやダークモード調整など、配色の微調整はこの3軸を分けて考えるのが基本。

もっと詳しく
仕組み・特徴
色は 3 つの軸で捉える。色相（Hue）＝色の種類、彩度（Saturation）＝鮮やかさ、明度（Brightness）＝明るさ。同じダッシュボードでも、軸を変えるだけで印象が大きく変わる。
使いどころ
色調整の基本。1 度に 1 軸だけ動かすと、何が印象を変えたのかが分かる。
注意点
色相が同じでも、明度・彩度で印象も可読性も変わる。見た目だけで判断せず、数値で確認する。

6. タイポグラフィ・配色

ダークアンカー

Dark Anchor (Palette Technique)

淡い色だけで組んだパレットに、濃い色を1色だけ入れて全体を引き締める配色テクニック。例：Serum Blush #F8D7DA などの淡色群に Beauty Shadow #3A2A2C を加えた「Warm Minimal」パレット。文字やボタンの色はこの濃色が担うと、淡い世界観のまま実用性が確保できる。

もっと詳しく
仕組み・特徴
淡い色だけのパレットはぼやけて「霧」のようになる。濃い色を 1 色だけ入れると、コントラストが生まれ、柔らかさが際立つ。
使いどころ
文字やボタンなど、要所をその濃色が担う。2 色コンビ（濃＋淡）や 5 段グラデーションでも同じ構造で、背景と文字の役割分担がそのまま決まる。
注意点
濃色を増やしすぎると柔らかい世界観が失われる。アンカーは 1 色が基本。
